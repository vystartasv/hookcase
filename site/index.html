Deterministic webhook fixtures / hookcase

Make webhook signatures boring.

Create, check, and diff a reproducible HTTP request fixture from one event document and one environment-only secret.

The useful boundary

Put the signature contract in a fixture.

Hookcase narrows the problem to the parts integrations actually compare: exact body bytes, owned headers, and a reproducible artifact.

01 / create

Canonicalize once.

Turn a checked-in event into stable JSON body bytes, sorted headers, deterministic IDs, and the documented HMAC fields.

02 / check

Catch drift locally.

Validate fixture shape, body/header/timestamp agreement, bounds, and the signature using the named environment variable.

03 / diff

Review exact changes.

Report deterministic field changes and SHA-256 hashes for the two exact body strings without requiring the secret.

How it works

Event document to checked artifact.

Describe

Keep the event, body, timestamp, and selected headers in JSON.

Sign

Read one explicitly named environment variable, never from the file.

Emit

Write stable fixture JSON with canonical body bytes and owned headers.

Check

Recompute and compare the contract, bounds, and HMAC locally.

Diff

Compare exact fields and body hashes without replaying a request.

Security and boundaries

The fixture stays on your machine.

Included

POST + JSON fixtures, canonical body bytes, sorted headers, bounded timestamps, HMAC-SHA256, environment-only secret input, and stable exit codes.

Not included

No network, listening socket, receiver, tunnel, delivery service, proxy, replay, provider-specific dialects, or secret store.

Security posture: secrets are read from one named environment variable and are not persisted or intentionally printed. Header injection, forbidden transport/authentication headers, duplicate JSON keys, and oversized bodies are rejected.

Quickstart

Create a fixture in a few commands.

Requires Bun. The event timestamp is explicit, so the example output is byte-stable.

bun install --frozen-lockfile
export HOOKCASE_SECRET='replace-me-locally'
bun run src/cli.ts create examples/event.json --secret-env HOOKCASE_SECRET --out /tmp/hookcase-fixture.json
bun run src/cli.ts check /tmp/hookcase-fixture.json
bun run src/cli.ts diff /tmp/hookcase-fixture.json /tmp/hookcase-fixture.json

Verification / local evidence

What the repository checks

  • Creation and checking with a known HMAC vector.
  • Malformed/duplicate JSON, bounds, and forbidden headers.
  • Deterministic diff, stable exit codes, and secret non-persistence.
  • Ten passing tests in the authoritative Bun runner.

This is local evidence and documented scope—not proof of remote delivery, provider acceptance, adoption, or time saved.
